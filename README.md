# gitSynth

A real-time guitar synthesizer for REAPER, written in JSFX. It works from the guitar's own audio on an ordinary mono cable: no MIDI, no hex pickup, no samples. Every control is a plain slider, so the plugins are fully usable with a screen reader.

## Status

This is a work in progress. [PLAN.md](PLAN.md) has the design and the build steps, with what is done.

- **Part 1, processed guitar:** working. It reshapes the string's own sound, works on chords, and needs no pitch tracking.
- **Part 2, tracked voice:** working on single notes. A pitch tracker drives oscillators or a waveguide flute.
- **Not yet done:** combining Parts 1 and 2 into one plugin, and more physical models.

## The plugins

All plugins are in [jsfx](jsfx).

- **gitSynth Part 1** (`gitSynth-part1.jsfx`): processed guitar. Its stages are:
  - envelope reshaping: swell, sustain, Hold and gate
  - waveshaper
  - envelope-swept resonant filter
  - violin, viola or cello body resonance
  - vowel filter
  - frequency-shifter ensemble
  - vibrato with delayed onset

  The sliders are grouped, with a free number after each group.
- **gitSynth Part 2** (`gitSynth-part2.jsfx`): tracked voice, for single notes.
  - **Voices:** a sine, band-limited triangle, saw, square or pulse oscillator, or a waveguide flute.
  - **Pitch:** follow your playing exactly, or snap to semitones, with glide and transpose.
  - **Note logic:** handles pick noise, mutes and touched strings.
  - **Testing:** channels 3 and 4 carry the tracked pitch and its confidence, for the test tools.
- **gitSynth Tuner** (`gitSynth-tuner.jsfx`): an accessible tuner.
  - **Readout:** read-only sliders for note, octave, cents and flat, in tune or sharp, which a screen reader can read in REAPER's parameter list.
  - **Audio cue:** clicks whose speed and pitch say how far off you are and in which direction, or a reference tone to tune against by ear.
- **gitSynth Frequency Shifter Ensemble** (`gitSynth-freqshift.jsfx`): Part 1's ensemble as a standalone stereo effect.

Feed the plugins a clean DI signal, and put other effects after them.

## Installing

REAPER loads JSFX from its Effects folder: in REAPER, choose Options, then Show REAPER resource path, and open `Effects`. The plugins need the `lib` and `cookdsp` folders beside them.

- **To copy:** copy everything inside `jsfx` (the `.jsfx` files and the `lib` and `cookdsp` folders) into a folder of your own under `Effects`, for example `Effects/gitSynth`.
- **To link, for development:** make a folder link (a Windows junction) from `Effects/gitSynth-dev` to this repository's `jsfx` folder. REAPER then always loads the current code, with nothing to copy. In PowerShell:

  ```
  New-Item -ItemType Junction -Path "$env:APPDATA\REAPER\Effects\gitSynth-dev" -Target "<path to repository>\jsfx"
  ```

  The test tools expect this link.

## Reusing the libraries

The DSP building blocks in `jsfx/lib` are standalone objects that any JSFX can import:

- state-variable filter
- envelope follower, gate and attack detector
- waveshaper
- frequency shifter, LFO and ensemble
- vibrato
- vowel filter
- pitch tracker and its note logic
- waveguide flute

The [library guide](jsfx/lib/README.md) covers how to import them, the conventions they follow, each object's functions and parameters, known pitfalls, and how to add a new library.

The plugins are built from these libraries. What remains in each plugin file is mostly that plugin's own wiring: smoothing its sliders, sustain, swell and the body resonance in Part 1; pitch shaping, oscillator choice and the flute's breath envelope in Part 2; the readout and audio cues in the tuner.

## Testing

The tools render clips through the real JSFX, using REAPER from the command line, and measure the result. Windows only, for now.

### Setup

1. Install Python 3, then from the repository folder:

   ```
   python -m venv .venv
   .venv\Scripts\python -m pip install -r tools\requirements.txt
   ```

2. Make the `gitSynth-dev` link described under [Installing](#installing).
3. `tools/render.py` expects REAPER at `C:\Program Files\REAPER (x64)\reaper.exe`; edit `REAPER` in that file if yours is elsewhere.

### Running

- **REAPER must be closed:** the tools refuse to run while it is open. They start REAPER on a hidden Windows desktop, so it never appears or takes focus.
- **`tools/reference_pitch.py`:** makes a reference pitch file for each clip, in `results/reference/`, using librosa's pYIN and YIN. Run it after adding or re-recording clips.
- **`tools/render.py CLIP --plugin NAME.jsfx --set slider=value ...`:** renders one clip.
  - Sliders are given by their variable names.
  - Add `--channels 4` to keep Part 2's test channels.
  - `render_batch()` in the same file renders many clips in one REAPER run.
- **`tools/track_all.py`:** renders every clip through Part 2 and reports, for each clip, lock time, pitch error, octave-type errors and gaps.
- **`tools/glitch.py` and `tools/onset_junk.py`:** measure wrong-pitch sound, sound after a note ends, and behaviour just after each pick.
- **`tools/refactor_check.py`:** for reorganising code without changing the sound. `save` renders fixed cases through all four plugins as a baseline; run it again without arguments after a change, and it reports any difference.

The reference pitch marks notes about 50 ms before the actual pick, because pYIN uses centred windows. The tools measure note starts from the pick itself.

## Accessibility

- **No custom graphics:** every control is a slider, so REAPER's own parameter list, and screen readers through it, can reach everything.
- **Ordered sliders:** they're grouped in a logical order, with a free number after each group, so future controls can join their group without renumbering. Renumbering would break saved presets and projects, which store values by slider number.
- **Readable status:** read-only status, such as the tuner's readout, is written to sliders that a screen reader can read.
